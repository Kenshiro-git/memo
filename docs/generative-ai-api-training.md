# 第1章：生成AIとAPIの基礎知識

## 目的
生成AI APIとは何かを理解し、チャット型AIサービスとの違い、APIのメリット、代表的なAPIの種類と特徴を把握する。

### 1-1. 生成AIとは
- 生成AIの基本的な仕組み
- テキスト・画像・音声などを生成・分析する技術
- 生成AIでできること、できないこと

### 1-2. APIとは
- API（Application Programming Interface）の概念
- システム間で機能やデータをやり取りする仕組み
- APIを利用するメリット

### 1-3. ChatGPTと生成AI APIの違い
- チャット画面から直接利用する方法
- プログラムやシステムからAPIを利用する方法
- 自動化や大量データ処理
- API利用に必要な管理や設定

### 1-4. APIのメリットと制約
- 既存システムとの連携、定型業務の自動化、大量データ処理
- APIの利用制限、応答時間、処理性能、回答精度、料金

### 1-5. 主な生成AI APIの種類と特徴
生成AI APIは複数の企業から提供され、モデルやサービスによって機能・性能・料金体系が異なる。

| 提供企業 | API・サービス名 | 主な特徴 |
|---|---|---|
| OpenAI | OpenAI API（GPTシリーズなど） | 文章生成、要約、翻訳、画像理解、プログラミング支援 |
| Anthropic | Claude API | 長文分析、文書作成、プログラミング支援 |
| Google | Gemini API | 文章、画像、音声、動画などのマルチモーダル処理 |
| Microsoft | Azure OpenAI | Azure環境からOpenAIのモデルを利用 |
| AWS | Amazon Bedrock | AWS環境から複数企業の生成AIモデルを利用 |
| Cohere | Cohere API | 文章生成、検索、分類、検索支援 |

**主な用途**
- 文章生成・要約：メール下書き、議事録要約、報告書
- 文章分析・分類：問い合わせ分類、アンケート分析
- 画像理解・生成：画像の説明、デザイン案
- 音声処理：文字起こし、音声生成
- プログラミング支援：コード生成、修正、レビュー
- 文書検索支援：社内資料の検索、関連情報抽出

**選択時の確認事項**
- 目的に合う機能、回答精度、処理性能
- トークン課金体系、利用制限
- 個人情報・機密情報の取り扱い
- 既存システムとの連携、管理機能
- 会社が承認したサービス・モデルであること

※モデル・機能・料金体系は変更される場合がある。Amazon BedrockやAzure OpenAIはクラウドサービスを経由してモデルを利用する仕組み。

# 第2章：生成AI APIの利用方法

## 目的
APIの基本知識を理解し、リクエスト送信からレスポンス取得までの流れを把握する。

### 2-1. APIの利用開始
- 利用アカウント、権限、社内申請・承認
- 利用環境の準備と利用可能モデルの確認

### 2-2. APIキーとは
- APIキーの役割と認証
- APIキーとアカウント・プロジェクトの関係
- APIキーの適切な取り扱い

### 2-3. AIモデルの選択
- モデルの種類、性能・処理速度の違い
- 用途による使い分け
- モデル別の料金・利用制限

### 2-4. プロンプトとは
- AIへの指示文の概念と作成方法
- 明確な指示の重要性
- 入力データと指示文の違い
- 不要な情報を含めない工夫

### 2-5. リクエストとレスポンス
- リクエストとレスポンスの意味
- 送信情報と取得できる情報
- JSON形式の基本
- API利用から結果取得までの流れ

### 2-6. APIエラーへの対応
- 認証エラー、リクエスト不備
- レート制限、タイムアウト、サービス障害
- エラー確認と問い合わせ先

# 第3章：トークンの仕組みと料金管理

## 目的
料金発生の仕組みを理解し、利用者と管理者がそれぞれ適切にトークン・利用料金を管理できるようになる。具体的な単価や料金例は扱わない。

### 3-1. トークンとは
- AIが文章を処理する際の単位
- 文字数とトークン数の違い
- 日本語と英語の分割の違い
- モデルごとに分割方法が異なる場合がある

### 3-2. 入力トークンと出力トークン
- 入力トークン（Input Tokens）：指示文、入力文章、会話履歴など
- 出力トークン（Output Tokens）：AIが生成する回答など
- 回答内容に応じて出力トークン数が変化する
- モデルによって内部の推論に使用するトークンが発生する

### 3-3. API料金が発生する仕組み
- 主に入力・出力トークンの利用量に応じて課金
- 入力と出力で料金体系が異なる場合がある
- モデルによって料金体系が異なる
- リクエスト数や処理対象データが増えると総利用量が増える
- 会話履歴の再送信で入力トークン数が増える
- 画像・音声・ツール利用などには別の課金要素がある場合がある
- キャッシュされた入力には異なる料金体系が適用される場合がある

### 3-4. 利用者ができるトークン・料金管理

**プロンプトの最適化**
- 指示を明確にし、不要な文章・重複入力を減らす
- 必要な条件や情報を整理して送る
- 精度を保ちながら無駄を削減する

**入力データの管理**
- 必要なデータだけを送信する
- 大量文書の一括送信が必要か検討する
- 不要な会話履歴を送らない
- 処理対象の量を事前に確認する

**出力トークンの管理**
- 必要な回答の長さ・形式を指定する
- 過度に詳細な出力を避ける
- 必要に応じて出力トークン上限を設定する

**モデルの使い分け**
- 処理内容に適したモデルを選ぶ
- 簡単な処理には軽量モデルを検討する
- 精度・速度・コストのバランスを考える

**不要なAPI利用の防止**
- 同じ処理の重複実行を避ける
- エラー時に無制限に再実行しない
- 大量処理前に少量でテストする
- 定期実行・自動処理の設定を確認する
- 利用可能なら自身の利用状況を確認する

### 3-5. 管理者ができるトークン・料金管理

**利用状況の可視化**
- 総利用量、入力・出力トークン数の把握
- 部署別・利用者別・プロジェクト別の利用分析
- モデル別、日別、月別の推移確認

**予算と利用上限の管理**
- 部署・プロジェクト別の予算設定
- 利用料金アラート
- 上限到達時の対応ルール
- 必要に応じたAPI停止の仕組み
- 予算超過の原因調査

※予算アラートは自動停止と同義ではない。実際の制御機能は事業者や社内システムによって異なる。

**レート制限**
- 一定時間あたりのリクエスト数・トークン量の制限
- 短時間の大量リクエストの抑制
- 利用者・システム別の制限

※レート制限だけでは月間料金の上限は保証されない。

**モデル利用の管理**
- 利用可能モデルの制限
- 用途別の推奨モデル
- 高コストモデルの利用管理

**異常利用の検知**
- 急激なトークン増加、大量リクエスト、重複処理の検知
- APIキー不正利用の調査
- 異常時の通知・停止方法

**利用ログの管理**
- 実行回数、モデル、トークン数、エラーの記録
- 保存期間と閲覧権限の管理
- 機密情報をログに残さない工夫

### 3-6. トークン・料金管理の注意事項
- トークン削減だけを目的にしない
- 入力を削りすぎると回答精度が低下する場合がある
- 再実行が増えると結果的に利用量が増える
- 処理が失敗しても状況によって料金が発生する場合がある
- レート制限、予算管理、利用停止は異なる仕組み
- 品質と利用コストの両立が重要

# 第4章：セキュリティと情報管理

## 目的
情報漏えいや不正利用のリスクを理解し、会社の情報資産を安全に取り扱う。

### 4-1. APIキーの管理
- APIキーは重要な認証情報
- 他人と共有しない
- ソースコードや公開リポジトリに記載しない
- 社内チャット・メールへの不用意な貼り付けを避ける
- 流出時は速やかに報告し、管理者が無効化・再発行する

### 4-2. 個人情報の取り扱い
- 個人情報の範囲を理解する
- 氏名・住所・電話番号・メールアドレスなどの取り扱い
- 社内ルールに従って送信可否を判断する
- 必要に応じて匿名化・マスキング
- 必要な場合は承認を得る

### 4-3. 機密情報の取り扱い
- 公開情報と社内情報の違い
- 社外秘資料、顧客情報、契約書、売上情報、未公開資料の送信条件
- 送信可能・承認必要・禁止の分類
- 社内の情報分類ルールに従う

### 4-4. APIに送信したデータの取り扱い
- APIに送った情報は外部事業者に渡る
- 事業者によるデータ保持の仕組み
- モデル学習への利用の有無
- 保存期間・削除条件
- 利用規約や契約条件の違い

### 4-5. アクセス権限の管理
- 必要最小限の権限
- 異動・退職時の権限見直し
- 利用目的に応じたアクセス範囲
- 管理者と一般利用者の権限分離

### 4-6. 利用ログと監査
- 利用履歴の記録目的
- 利用者・日時・異常利用の確認
- ログに含まれる個人情報・機密情報の保護
- 保存期間と閲覧権限

### 4-7. インシデント発生時の対応
- APIキー流出
- 機密情報の誤送信
- 不正利用
- 想定外の大量リクエスト
- 管理者への報告、利用停止、原因調査、再発防止

# 第5章：生成AI APIのリスクと注意事項

## 目的
生成AI特有のリスクと技術的な問題を理解し、出力結果を適切に判断・利用する。

### 5-1. ハルシネーション
- 誤った情報や存在しない出典を生成する可能性
- もっともらしい回答も正しいとは限らない
- 重要な情報は一次情報と照合する

### 5-2. 回答の検証と品質管理
- 内容・数値・計算結果を検証する
- 重要な判断は人間が行う
- 業務上の責任を明確にする
- 必要に応じて複数の方法で検証する

### 5-3. 著作権と知的財産
- 入力データの著作権
- 生成した文章・画像の取り扱い
- 第三者の権利侵害の可能性
- 商用利用と利用規約の確認

### 5-4. バイアスと不公平な回答
- 学習データ等に起因する偏り
- 特定の人物・属性に対する不公平な判断
- 採用・人事評価等での注意
- AIの判断を無条件に採用しない

### 5-5. プロンプトインジェクション
- 外部文書・Webページに含まれる悪意ある指示
- AIが本来と異なる動作をする可能性
- 外部データを無条件に信用しない
- AIに必要以上の操作権限を与えない

### 5-6. APIの障害とエラー
- 事業者側の障害、ネットワークエラー
- タイムアウト、レート制限
- モデル提供状況の変更
- 再試行方法と問い合わせ先

### 5-7. 大量実行・重複実行のリスク
- 大量リクエスト、無限ループ、重複実行
- エラー時の過剰な再試行
- 想定外のトークン消費と料金増加
- 実行件数と利用上限の事前確認

### 5-8. AIへの過度な依存
- AIの回答は必ずしも正確ではない
- すべての判断をAIに任せない
- 出力を確認せず外部公開しない
- AIによる操作の影響範囲を把握する
- 重要操作には人間の確認・承認を設ける

# 研修全体の重要ポイント

1. **APIの仕組みを理解する**：生成AIを業務システムや処理に組み込める。
2. **トークンと料金の関係を理解する**：利用者は無駄を減らし、管理者は利用量・予算・制限を管理する。
3. **セキュリティを意識する**：APIキーや機密情報を社内ルールに従って取り扱う。
4. **生成AIのリスクを理解する**：誤回答、情報漏えい、不正な指示などを想定する。
5. **適切な管理のもとで利用する**：安全性、品質、コストのバランスを意識する。
